# Rapid Prototyping Model

## Summary

Still a **linear model** — but "**rapid**". A working prototype is built early to
get something concrete in front of the client, rather than relying on a
specification document alone.

## Key points

- It attacks the **first** waterfall problem (validation only at the end) without
  abandoning the linear shape.
- It is the base that the **[[spiral-model]]** builds on: the spiral model is
  described exactly as *"rapid prototyping model plus risk analysis preceding
  each phase"*.

## Watch out for

- Being linear, it does not solve the incremental-delivery problem. There is
  still one real product, delivered once — the prototype is a communication
  device, not a release.
