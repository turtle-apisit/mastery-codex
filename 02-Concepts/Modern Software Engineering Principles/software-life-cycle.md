# Software Life-Cycle

## Summary

The **software life-cycle** is *the period of time that begins when a software
product is conceived and ends when the software is no longer available for use.*

Three stages:

```
Development  --deliver-->  Maintenance  --no longer needed-->  Retirement
```

**Software development in theory** is **linear** and **starts from scratch**.
**In the real world**: we make mistakes, and we do not start from scratch.

**Two shapes of development project:**

- **1-shot project** — e.g. school homework. Build it, hand it in, done.
- **Continuous development** — e.g. Facebook, MS Teams, NewAcis. **Incremental**
  and **subject to changes** (COVID-19, Windows XP support terminating).

**Software artifacts** — which of these count as parts of the software?
**Code**, **data structures**, and **documents**. All three.

## Key points

- The life-cycle covers far more than the build. Development is one stage of
  three, and it is usually the shortest.
- The theory-versus-reality gap is the argument the rest of the class is built
  on: every lifecycle model is an attempt to cope with the fact that the linear,
  from-scratch ideal does not hold.

## Watch out for

- Documents are part of the software, not commentary about it. This is why the
  cost of correcting a fault is low early on — *usually just a document needs to
  be changed*.
